# How to Use This Capstone

> Treating the Capstones like a real interview.

---

## The Rules of Engagement

Do not simply read the prompt and immediately scroll down to the solution. If you do that, you are wasting the most valuable resource in this book.

To get the most out of these Capstone projects, you must simulate the pressure of a real interview.

### 1. Set a Timer
You have exactly **45 minutes** for each project.
- Minutes 0-15: Understand, Match, Plan.
- Minutes 15-35: Implement.
- Minutes 35-45: Dry Run and Debug.

### 2. Disable Autocomplete
Open a blank text editor or a standard LeetCode playground with autocomplete turned off. You must rely on your own memory for Python syntax.

### 3. Think Out Loud
Even if you are alone in your room, you must talk out loud. Explain your Brute Force approach. Explain why you are choosing a Hash Map over an Array. This builds the exact muscle memory you will need on interview day.

### 4. Write Pseudo-code First
Do not write a single line of Python until you have written 3-4 lines of English pseudo-code as comments, and you have mathematically proven your Big O time complexity.

### 5. Dry Run Manually
When you finish coding, do not hit "Run". Manually trace a test case using code comments. Catch your own bugs.

---

## Grading Yourself

After the 45 minutes are up (or after you finish), compare your solution to the provided walkthrough.

Give yourself a "Hire" rating ONLY IF:
1. Your algorithm matches the optimal Time/Space complexity.
2. Your code works without syntax errors.
3. You caught your own edge cases (empty inputs, etc.) before running the code.

If you fail, review the pattern you missed, re-read the associated chapter in this book, and try the next Capstone tomorrow.
